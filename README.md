# Forma Lab — локальный учебный уязвимый стенд

> **УЧЕБНЫЙ УЯЗВИМЫЙ СТЕНД. ТОЛЬКО ДЛЯ ЛОКАЛЬНОГО ТЕСТА. НЕ ВЫКЛАДЫВАТЬ В СЕТЬ.**

Намеренно уязвимое учебное приложение для лабораторных работ и локальной проверки анализаторов. Это не рабочий магазин. Сайт оформлен как магазин вымышленных товаров; в игровом режиме 20 дел, подсказки, уровни, XP и достижения. Используются только тестовые данные.

## Запуск

Требуется Python 3.10+ и зависимости из `requirements.txt`:

```sh
pip install -r requirements.txt
python app.py
```

Откройте <http://127.0.0.1:5000>. `run.sh` запускает то же приложение. Для Docker используйте host networking, чтобы процесс сохранил bind на loopback хоста (поддержка зависит от Docker-платформы):

```sh
docker build -t forma-lab .
docker run --rm --network host forma-lab
```

Приложение фиксирует bind на `127.0.0.1:5000`; адрес и порт нельзя переопределить переменными среды. Не проксируйте и не публикуйте его. Debug mode включён намеренно для VC12.

## Учетные данные и фиктивные секреты

- `admin` / `admin`
- `test` / `123456`
- `.env` и константы в коде содержат только detector-shaped **FAKE** значения. Они не принадлежат реальным аккаунтам или сервисам и нигде не используются для внешних вызовов.
- `static/legacy.js`, `static/legacy.php` и `static/test.php` — статические исходники для анализатора. Flask их не импортирует и PHP не исполняет.
- В `requirements.txt` есть намеренно устаревший `Django==2.2.23` для обнаружения CVE-2021-33571. Приложение Django не использует; факт затронутой версии приведён в [NVD](https://nvd.nist.gov/vuln/detail/cve-2021-33571).

## Страницы магазина и проверка сканером

Обычная навигация ведёт в каталог, карточки товаров, профиль, заказы, оформление и доставку. Формы серверных страниц доступны HTML-crawler-ам напрямую; уязвимые сценарии расположены в соответствующих частях магазина, а общая карта уязвимостей не публикуется. Некоторые задания игрового режима создают формы JavaScript-кодом и для их обхода нужен browser/headless режим сканера.

## Лабораторные сценарии

В каждом уязвимом участке `app.py` и статических фикстур есть комментарии `VULN`, CWE, УБИ и/или категория BDU. В игровом интерфейсе класс дефекта скрыт, пока задание не раскрыто.

- **VC01–VC13:** hardcoded fake key, `.env` в репозитории, слабый seeded пароль, вход без rate limit, доверие `X-Forwarded-For`, IDOR заказов, подмена клиентской оплаты, localhost-only SSRF, отсутствие CSRF, отсутствующие CSP/X-Frame-Options, `random.randint` для сброса пароля, локальный debug и статический `phpinfo`, wildcard CORS.
- **BDU:W01:** SQLi, отражение HTML/XSS, безопасная симуляция command injection через echo, SSTI marker, XXE marker.
- **BDU:W02:** IDOR, ограниченное чтение `/etc/passwd` и фиктивного каталога.
- **BDU:W03:** маркер небезопасной десериализации; payload не десериализуется.
- **BDU:W04:** слабая аутентификация, код восстановления, CSRF и слабая demo-cookie.
- **BDU:W05:** SSRF только на локальную fixture, upload, wildcard/missing headers, DoS/ReDoS симуляция и синтетическая DNS запись.

## Безопасные границы демонстраций

- Сервер слушает только loopback на `127.0.0.1:5000`; внешних интеграций нет.
- Данные SQLite — только вымышленные товары, заказы, пользователи и чеки.
- `/api/fetch` принимает только `http://127.0.0.1:5000/api/ssrf-fixture` или localhost-эквивалент. Переадресации и внешние хосты не разрешены; таймаут 0.8 с, тело ответа не больше 1 МБ.
- `/api/file` допускает только локальный `/etc/passwd` (до 4096 байт) или фиктивную карту файлов; произвольные пути не открываются.
- Командный сценарий ничего не запускает через shell/subprocess. SSTI, XXE и десериализация только распознают маркеры.
- Файлы сохраняются в `uploads/`, максимум 1 МБ; сервер их не обслуживает и не исполняет.
- DoS — арифметическая симуляция максимум 20 условных запросов; ReDoS принимает максимум 1 МБ, использует безопасный regex и ограниченную работу.
